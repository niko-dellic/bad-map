Install

npm install bad-map maplibre-gl

MapLibre GL JS is a peer dependency. The default keyless tile source is OpenFreeMap.

Quick start

import { Map } from "maplibre-gl";
import { LowResBasemap, streets, transit } from "bad-map";
import "maplibre-gl/dist/maplibre-gl.css";

const map = new Map({
  container: "map",
  center: [-74.006, 40.7128],
  zoom: 14,
  style: { version: 8, sources: {}, layers: [] },
});

const basemap = new LowResBasemap({
  source: { tileJSON: "https://tiles.openfreemap.org/planet" },
  layers: [streets(), transit({ enabled: false, priority: 20 })],
  colorMode: "greyscale",
  cell: { width: 8, height: 16, dotSize: 2 },
});

await basemap.addTo(map);
basemap.setLayerVisible("transit", true);

Give the MapLibre container an explicit size. Create and attach the basemap in the browser after that container exists.

Functionality

bad-map renders vector-tile meaning onto a coarse square-dot lattice. It does not pixelate a screenshot of a finished map.

  • Semantic packs for streets, transit, topographic, weather, political, marine, and land-use data.
  • Dark and light themes, greyscale or color, configurable cell and dot sizes, labels, locale, and feature interaction.
  • Named MVT sources with TileJSON discovery, request concurrency, retry, cache, and time-key controls.
  • Stable render slots for basemap, buildings, data, markers, labels, fog, and interaction.
  • Optional dithered or regular atmospheric fog and native 3D OpenMapTiles building extrusions.

What it plays with

Thing Relationship
MapLibre GL JS The host map and required peer dependency.
OpenFreeMap The default keyless vector-tile source.
MVT / OpenMapTiles Built-in packs read MVT and expect OpenMapTiles property conventions. Custom named MVT sources are supported.
Native MapLibre layers Insert them into the stable layer slots. They remain crisp, interactive, and outside basemap theme changes.
deck.gl It can coexist with deck.gl layers and consume the same parsed datasets, but has no deck.gl runtime dependency.
SSR frameworks Import and initialize from a client-only component. Rendering the map on the server is out of scope.

Data layers

Package-owned layers are registered by ID and rendered below labels. Their palettes stay intact when the basemap switches to greyscale.

heatmap
Weighted [longitude, latitude, weight] triplets, accumulated and dithered on the worker.
geojson
Points, lines, polygons, multi-geometries, and geometry collections with constant or accessor-based styling.
waypoint
Lattice-aligned locator targets and caret glyphs with optional per-item styling.
trips
Timestamped paths with play, pause, seek, step, loop, speed, and trail controls.

Picking is available through queryDataFeatures and typed enter, leave, and click events. Fetching input URLs remains the host application's job.

Camera modes

Mode Use it when Behavior
surface You want pitch, rotation, fog, or buildings. The default. Dots sit on a flat Web Mercator plane and foreshorten in perspective. Labels billboard by default.
screen You want dots locked square to the viewport. Supports pan, zoom, and bearing, but not pitch.

Runtime controls

The main LowResBasemap controls are grouped below.

  • Lifecycle: addTo, remove, refresh.
  • Appearance: setTheme, setColorMode, setCell, label, locale, fog, and building controls.
  • Cartography: setSource, setSources, setSourceTime, setLayers, and setLayerVisible.
  • Data: heatmap compatibility methods plus data-layer CRUD, trip playback, selection, and feature queries.
  • Camera: setProjectionMode and setCamera.

The package ships TypeScript declarations and typed load, render, error, feature, selection, style, layer, time, projection, building, fog, and heatmap events. The README API list is the compact method reference.

Demo versus package

The demo shows the package, then adds a few bad ideas of its own.

Feature Exported by bad-map?
Semantic map, data layers, fog, buildings Yes.
Screen-space vignette and fisheye No. They are demo-only effects.
Place search and settings interface No. They belong to the demo application.

Limitations

  • Requires a browser, DOM, canvas, WebGL 2, and Web Workers.
  • Uses Web Mercator.
  • Built-in semantic packs currently require MVT sources.
  • Screen mode supports bearing but not pitch.
  • Surface mode is an experimental flat plane. Terrain elevation is not supported.
  • Numeric data is categorical or quantized; this is not a general raster engine.
  • 3D buildings expect OpenMapTiles building properties and remain smooth native geometry by design.
  • Source attribution must remain visible, either through MapLibre's attribution control or an equivalent supplied by the host app.
